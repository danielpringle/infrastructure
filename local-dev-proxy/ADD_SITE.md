# Adding a New Site

Assume the new site is `mysite.local`.

## 1. Clone the proxy-compatible WordPress environment

From the `infra` directory:

```bash
cp -R wordpress-proxy mysite
cd mysite
```

## 2. Update `.env`

```dotenv
PROJECT_NAME=mysite
DOMAIN=mysite.local
WP_TITLE="My Site"
DB_NAME=mysite
```

No phpMyAdmin or Mailpit host-port variables are required.

## 3. Check the project Nginx configuration

The project Nginx should listen on HTTP only:

```nginx
server {
    listen 80;
    server_name ${DOMAIN};

    ...
}
```

The shared proxy handles HTTPS.

## 4. Check container names

Use `${PROJECT_NAME}` for the services exposed through the proxy:

```yaml
nginx:
  container_name: ${PROJECT_NAME}-nginx

phpmyadmin:
  container_name: ${PROJECT_NAME}-phpmyadmin

mailpit:
  container_name: ${PROJECT_NAME}-mailpit
```

For `mysite`, this produces:

```text
mysite-nginx
mysite-phpmyadmin
mysite-mailpit
```

These names are used by the shared proxy.

## 5. Connect proxy services to the shared network

Nginx, phpMyAdmin and Mailpit need to be connected to both the project network and the shared proxy network:

```yaml
networks:
  - wordpress
  - proxy
```

The external network is:

```yaml
networks:
  wordpress:

  proxy:
    external: true
    name: dpuk-proxy
```

Do not publish host ports for phpMyAdmin or Mailpit.

## 6. Add the domains to `/etc/hosts`

```bash
sudo nano /etc/hosts
```

Add:

```text
127.0.0.1 mysite.local
127.0.0.1 db.mysite.local
127.0.0.1 mail.mysite.local
```

## 7. Test hostname resolution

```bash
ping mysite.local
ping db.mysite.local
ping mail.mysite.local
```

Each should resolve to:

```text
127.0.0.1
```

## 8. Generate and trust SSL certificates

Run these commands from the `local-dev-proxy` directory.

### Step 1: Trust the local certificate authority

Run this once on your Mac:

```bash
mkcert -install
```

This allows your browser to trust certificates generated by `mkcert`.

### Step 2: Generate a certificate for your project

Example: `dan.local`

```bash
mkcert \
  -cert-file certs/dan.local.pem \
  -key-file certs/dan-key.local.pem \
  dan.local \
  db.dan.local \
  mail.dan.local
```

For another project, replace `mysite` with your project's domain name:

```bash
mkcert \
  -cert-file certs/mysite.local.pem \
  -key-file certs/mysite-key.local.pem \
  mysite.local \
  db.mysite.local \
  mail.mysite.local
```

One certificate covers all three hostnames: the main site, phpMyAdmin and Mailpit.

Generate a separate certificate and key for each project. Keep the filenames consistent with the paths used in Nginx.

## 9. Add the project virtual hosts to the shared proxy

### Step 1: Create the project's Nginx configuration

Create a configuration file in:

```text
local-dev-proxy/docker/nginx/conf.d/
```

For example:

```text
mysite.conf
```

### Step 2: Add three virtual hosts

Add server blocks for:

- `mysite.local` — WordPress site
- `db.mysite.local` — phpMyAdmin
- `mail.mysite.local` — Mailpit

Each server block should use the correct upstream container name and port, and the certificate and key generated in Section 8.

For example, the certificate lines for all three blocks should be:

```nginx
ssl_certificate     /etc/nginx/ssl/mysite.local.pem;
ssl_certificate_key /etc/nginx/ssl/mysite-key.local.pem;
```

Use the same certificate for all three hostnames because it covers all three domains.

### Step 3: Enable the virtual host

Add the configuration file to `local-dev-proxy/docker/nginx/nginx.conf`.

For example:

```nginx
include /etc/nginx/conf.d/mysite.conf;
```

Only include virtual hosts for projects you want the shared proxy to serve.

### Step 4: Rebuild the shared proxy

From the `local-dev-proxy` directory, run:

```bash
docker compose up -d --build --force-recreate
```

Check the proxy is running:

```bash
docker compose ps
```

## 10. Troubleshoot SSL certificate problems

If a site is unreachable or the browser shows **Not Secure**, work through these checks in order.

### Step 1: Check the certificate files

From `local-dev-proxy`:

```bash
ls -l certs/
```

Confirm the certificate and key files exist and their filenames match the paths in your Nginx configuration.

### Step 2: Check the certificate covers the correct domains

For example, for `dan.local`:

```bash
openssl x509 -in certs/dan.local.pem -noout -ext subjectAltName
```

Confirm the output includes:

- `dan.local`
- `db.dan.local`
- `mail.dan.local`

### Step 3: Check that the local certificate authority is trusted

Run this on your Mac:

```bash
mkcert -install
```

Then reload the site in your browser.

### Step 4: Check the proxy logs

```bash
docker compose logs --tail=50 nginx
```

Common errors:

- **`cannot load certificate`** — the certificate path is wrong or the file is missing.
- **Browser says `Not Secure`** — check certificate trust, expiry and hostname coverage.
- **Nginx is restarting** — check the logs for configuration errors or missing certificates.

### Step 5: Rebuild the proxy

After changing the Nginx configuration or replacing certificate files, run:

```bash
docker compose up -d --build --force-recreate
```

Check the proxy status:

```bash
docker compose ps
```

If it is still restarting, check the logs again before making further changes.


### WordPress

```nginx
server {
    listen 443 ssl;
    server_name mysite.local;

    ssl_certificate     /etc/nginx/ssl/mysite.local.pem;
    ssl_certificate_key /etc/nginx/ssl/mysite.local-key.pem;

    location / {
        proxy_pass http://mysite-nginx:80;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

### phpMyAdmin

```nginx
server {
    listen 443 ssl;
    server_name db.mysite.local;

    ssl_certificate     /etc/nginx/ssl/mysite.local.pem;
    ssl_certificate_key /etc/nginx/ssl/mysite.local-key.pem;

    location / {
        proxy_pass http://mysite-phpmyadmin:80;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

### Mailpit

```nginx
server {
    listen 443 ssl;
    server_name mail.mysite.local;

    ssl_certificate     /etc/nginx/ssl/mysite.local.pem;
    ssl_certificate_key /etc/nginx/ssl/mysite.local-key.pem;

    location / {
        proxy_pass http://mysite-mailpit:8025;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

## 10. Start the project

From the new project:

```bash
make start
```

Confirm the containers are running:

```bash
docker compose ps
```

You should have:

```text
mysite-nginx
mysite-phpmyadmin
mysite-mailpit
```

## 11. Rebuild the shared proxy

From `local-dev-proxy`:

```bash
cd ../local-dev-proxy
docker compose up -d --build
```

The proxy must be running after the project containers are available because it needs to resolve their Docker container names.

Check:

```bash
docker compose ps
```

## 12. Run the WordPress setup

From the new project:

```bash
cd ../mysite
make setup
```

## 13. Test all three URLs

```bash
curl -I https://mysite.local
curl -I https://db.mysite.local
curl -I https://mail.mysite.local
```

Then open:

```text
https://mysite.local
https://db.mysite.local
https://mail.mysite.local
```

## Basic Flow

```text
clone
  ↓
update .env
  ↓
check container names/networks
  ↓
add domains to /etc/hosts
  ↓
test hostname resolution
  ↓
generate SSL certificate
  ↓
add project .conf to local-dev-proxy
  ↓
start project
  ↓
rebuild shared proxy
  ↓
run WordPress setup
  ↓
curl test
```

The shared proxy owns ports `80` and `443`. Individual projects do not need host ports for their web, phpMyAdmin or Mailpit services.
